# Code of Conduct

## Purpose

PostNot is an AI-generated software project, but the community around it is still human. This Code of Conduct sets expectations for how we collaborate across issues, pull requests, reviews, release discussions, and project-linked spaces.

We want the project to feel clear, respectful, and safe for contributors, users, and maintainers.

## Expected Behavior

Examples of behavior that help this project:

- Be respectful, patient, and specific.
- Critique code, ideas, and outcomes without attacking people.
- Keep bug reports, reviews, and requests actionable.
- Share context, constraints, and reproduction steps in good faith.
- Respect privacy, security, and local-first user expectations.
- Review AI-generated output before posting it.
- Correct mistakes openly and without blame.

## Unacceptable Behavior

The following behavior is not acceptable in this project:

- Harassment, intimidation, hate speech, or discriminatory language
- Personal attacks, insults, or sustained hostile arguing
- Publishing or threatening to publish private information
- Posting exploit details, secrets, or sensitive user data in public channels
- Spam, bad-faith issue filing, or low-effort AI-generated noise
- Misrepresenting the origin, review status, or safety of a contribution
- Any other conduct that a maintainer reasonably determines makes participation unsafe or unproductive

## Scope

This Code of Conduct applies to:

- GitHub issues, pull requests, reviews, comments, and project boards
- Repository documentation and release notes
- Project website content and linked community spaces
- Private communication with maintainers that is directly related to the project

## Reporting

If you experience or witness behavior that violates this Code of Conduct, report it privately to the repository owner, `@tansdf`.

- Until the project publishes a dedicated conduct inbox, use a non-public contact method listed on the maintainer's GitHub profile or project website.
- Include links, screenshots, and any immediate safety concerns when possible.
- Do not open a public issue for Code of Conduct reports.
- If no private contact route is available when you need one, open a minimal public issue asking for a private reporting channel without posting incident details.

## Enforcement

Maintainers will review reports as fairly and confidentially as possible. Depending on severity and context, maintainers may:

- ask for a correction or apology
- remove content
- issue a warning
- temporarily restrict participation
- permanently remove a participant from project spaces

Retaliation against someone who reports a concern is itself a Code of Conduct violation.

## Maintainer Responsibilities

Maintainers are responsible for clarifying standards, applying them consistently, and protecting reporters from retaliation where possible. Not every disagreement is a conduct violation, but maintainers may still step in when behavior is making the project harder to use or maintain.
